# Independent Replay: NOAA Nolo Advisory Chronology & Polling Simulations

## 1. Algorithmic Replay Methodology

Unlike preliminary inspection scripts that mapped advisories to polling windows using manual lookups, this replay is **derived purely algorithmically** from the raw JSON snapshots.

For any given query or polling timestamp $T$, the active state of the NOAA feed is defined as:
$$S(T) = \operatorname{argmax}_{\{S_i \mid t_i \le T\}} (t_i)$$
where $t_i$ is the nominal capture timestamp derived from the snapshot filename.

An advisory $A$ is classified as **superseded / overwritten prior to $T$** if:
1. Advisory $A$ appeared in some earlier snapshot $S_j$ ($t_j \le T$).
2. The latest snapshot $S(T)$ active at time $T$ contains a different advisory $A' \ne A$.

### Phase Sensitivity & Outage Resilience
- **Phase Sensitivity**: Notice that for 60-minute polling, whether the poll fires at `:00` or `:30` does not change the capture of daytime intermediate advisories `42A`, `43A`, and `44A` because their active lifespan in the feed is approximately 3 hours.
- **Outage Recovery**: If a 15-minute or 30-minute lightweight poller experiences a temporary 2-hour network failure, it can recover missing intermediate advisories upon reconnection **only if** the advisory has not been superseded by the next cycle. Once superseded in `CurrentStorms.json`, the state is permanently lost from that single endpoint and must be recovered via the text archive (`public_a`).
